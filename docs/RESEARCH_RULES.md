# 教材リサーチルール（ながら勉強アプリ用）

- 版：2.0（2026-11-08）
- 対象：教材を作る人とAI（Claude、Antigravity、ChatGPT／Gemini の Deep Research など）
- **この文書だけを読めば、誰でも同じ品質の教材を作って提出できること**を目指している。ほかの資料を読む必要はない。

ルールの強さは次の3つの言葉で表す。

| 表記 | 意味 |
|---|---|
| **必須** | 守らなければ不合格。差し戻しになる |
| **推奨** | 基本は守る。守れない理由があれば報告書に書く |
| **禁止** | してはいけない。1か所でもあれば不合格 |

---

## 1. 何を作るのか

### 1.1 アプリのしくみ

「ながら勉強」は、家事や電話の仕事をしながら勉強するためのWebアプリ。

1. 教材（Markdownファイル）を、**20〜40秒で読める短いカード**（120〜220字）に自動で区切る。
2. **数分おきに1枚**カードを出す。
3. 読み終わったら、そのカードから**自動で作ったテスト**（4択・○×・答えを思い出す問題）を**1〜2問すぐに出す**。

テストは、AIではなく**書き方のルール**から機械的に作る（2.6）。だから、**書き方がそのまま問題の質になる**。

### 1.2 読者

- 片手がふさがっている。画面を見られるのは数秒〜数十秒。
- いつ中断されるかわからない。だから、**1枚のカードだけ読んでも意味がわかる**必要がある。
- 専門家ではない。テーマごとの想定レベルは6章に書く。

### 1.3 成果物（必須）

| 成果物 | 置き場所・名前 | 内容 |
|---|---|---|
| 教材ファイル | `materials/<テーマ>/NN-<英小文字の名前>.md`（例：`materials/cpp/03-memory.md`） | 本文だけ。1ファイル＝アプリの教材1つ |
| 出典ファイル | `materials/<テーマ>/SOURCES.md` | 見出しごとの出典（4.5） |
| 報告書 | 提出時に依頼者へ渡す（ai-vault を使う場合は `review/result-<タスク名>.md`） | 8章の形式 |

- `<テーマ>` は英小文字とハイフン（例：`world-history`、`security`）。
- `NN` は `01` からの2桁の連番で、学ぶ順番に並べる。
- 1ファイルの本文は **5,000〜8,000字**（空白と記号を除いて5,000字以上）。カードにすると25〜45枚になる。

## 2. 書き方のルール

### 2.1 全体の形（必須）

```
# ファイル全体のタイトル（例：C++の成り立ちと特徴）

## 小単元のタイトル

段落1（2〜4文）

段落2（2〜4文）

…（小単元1つで600〜1,000字）

用語1：説明（60字以内）
用語2：説明
用語3：説明

Q: 確認問題1
A: 答え1

Q: 確認問題2
A: 答え2

## 次の小単元
…
```

- `#` はファイルの先頭に1つだけ。アプリでは教材名として表示される。
- `##` が小単元。1ファイルに **6〜10個**。
- 見出しは本文にはならない。カードの上に「どこの話か」として表示される。

### 2.2 文と段落（必須）

- **1文は60字以内。** 長くなったら2文に分ける。
- **1段落は2〜4文。** 段落の間は空行を1つあける。
- **1枚のカードだけで意味が通るようにする。**「これ」「この」「その」「上記の」で前の段落を指す文は、段落の最初に置かない。
- 文末は「である」「だ」体か「です・ます」体の**どちらかにそろえる**（ファイルの中で混ぜない）。

### 2.3 太字（必須）

`**語**` で囲んだ語が、穴埋め問題の答えになる。

- 太字にするのは、その段落で**一番大事な名詞**（用語・人名・地名・出来事・制度・機能の名前）。**1段落に1〜2個**。
- 太字の語は**2〜15字**。文や長い句は太字にしない。
- **太字の語を、同じ文の中で2回書かない**（問題文に答えが見えてしまう）。
- **前後の文脈だけで答えが1つに決まる文**で太字にする。

| | 例 | 理由 |
|---|---|---|
| 良い | 1789年7月、パリの民衆が**バスティーユ牢獄**を襲撃した。 | 年・場所・出来事から答えが1つに決まる |
| 悪い | これを**市民革命**という。 | 「これ」が何かカードだけではわからない |
| 悪い | **ルイ16世**はルイ16世の時代に… | 答えが同じ文に出ている |
| 悪い | 重要なのは**データを守るためのさまざまな工夫**である。 | 長い句で、選択肢にならない |
| 悪い | 代表的な企業に**A社**やB社がある。 | B社も正解になりうる（正解が2つ） |

### 2.4 定義（必須）

大事な概念は、**最初に出てきたところで**次の形の1文で定義する。

> 〇〇とは、△△である。

- 〇〇は20字以内。文末は「である」「のこと」「をいう」「を指す」「です」「だ」のどれか。
- この形の文から「〇〇とは？」という問題が作られる。

### 2.5 数字（必須）

- 数字には**必ず単位を付ける**：年・月・日・%・人・円・ドル・個・回・倍・km・m・kg・g・℃・世紀・歳・時間・分・秒・nm など。
- 単位付きの数字は穴埋め問題になる。**覚える価値がある数字だけ**を書く（1つの `##` に3〜5個まで）。
- **時点を表す日付**は「2026年11月時点」「2025年現在」の形で書く（この形はアプリが問題にしない）。
- 見分けのつかない細かい数字（例：2,080億と2,081億）を、答えにすることになる書き方は避ける。概数でよい数は「約〜」と書く。

### 2.6 用語集と確認問題（必須）

各 `##` の最後に、次の2つを置く。

1. **用語集**：`用語：説明` の形で3〜5行。
   - 用語は20字以内。説明は60字以内で、**用語そのものを説明の中に書かない**。
   - 区切りは全角の「：」を使う。
2. **確認問題**：`Q:` と `A:` の組を2つ。
   - Aは1語〜1文で短く。
   - 本文を読めば答えられる問いにする。本文にないことを問わない。

### 2.7 禁止事項

- **禁止**：表、画像、URL、脚注、`[1]` のような出典番号、HTML。
- **禁止**：コードブロック（\`\`\`）とバッククォート（\`）。プログラミングの教材でも、コードは言葉で説明する。
- **禁止**：アスタリスク2つを、太字以外の目的で使うこと（例：掛け算の記号を2つ並べる）。
- **禁止**：本や記事、教科書の文章を**そのまま書き写すこと**。事実は調べてよいが、文は必ず自分の言葉で書く（著作権のため）。
- **禁止**：「〜と言われる」「〜とも」のように、ぼかして確認を逃げる書き方。確認できないことは書かない（4.3）。

## 3. 作業の手順

| 手順 | やること | 終わりの条件 |
|---|---|---|
| 1 | 依頼の確認：テーマ・範囲・レベルを6章（または依頼文）で確認する | 範囲がファイル単位に分かれている |
| 2 | 骨組み：ファイルごとに `##` の見出しを6〜10個決め、学ぶ順に並べる | 見出しだけで全体の流れがわかる |
| 3 | 調査：見出しごとに、ランクA・Bの情報源を探す（4章） | 書く予定の事実すべてに出典がある |
| 4 | 照合：年号・数字・固有名詞を2つ以上の情報源で照合する | 食い違いを記録した |
| 5 | 執筆：2章の書式で書く | 文字数が5,000〜8,000字 |
| 6 | 自己検査：7章のチェックを行い、問題文を読んで直す | すべてのチェックに合格 |
| 7 | 提出：教材・出典・報告書を出す（8章） | 依頼者に渡した |

## 4. 情報源のルール

### 4.1 情報源のランク（必須）

| ランク | 情報源 | 使い方 |
|---|---|---|
| A | 公的機関・国際機関・業界団体の資料、法令（e-Gov など）、企業の公式IR・プレスリリース、教科書・学術書、大学・博物館の解説、規格の公式文書 | 年号・数字・固有名詞・定義の根拠にする |
| B | 大手報道（日経、Reuters、Bloomberg、NHK など）、専門メディア、百科事典（コトバンク、ブリタニカなど）、分野の専門家が書いた解説 | Aで確認できないときの根拠。**2つ以上のBで照合する** |
| C | Wikipedia、まとめサイト、個人ブログ、SNS、AIの回答 | **入口としてだけ使う。Cだけを根拠に書くのは禁止** |

### 4.2 照合（必須）

- **年号・数字・人名・地名・規格名・法律名は、2つ以上の情報源で照合する。**
- 情報源の間で食い違ったときの優先順：
  1. 公的機関・教科書の値
  2. 新しい資料の値
  3. 多数派の値
- 食い違いは、出典ファイルに「異説」として記録する（4.5）。
- 人名・王朝名の漢字やカタカナの表記は、日本の教科書や公的機関の表記に合わせる。

### 4.3 確認できなかったとき（必須）

- 確認できなかった事実は**書かない**。
- 数字が確認できなければ、数字を使わない書き方にする（例：「約40%」→「最大のシェアをもつ」。ただし、これも確認できる場合に限る）。
- 書かなかったことと、その理由を報告書に書く。

### 4.4 変わりやすい情報（必須）

- 市場シェア・売上・ランキング・最新技術・法律の施行状況・規格の策定状況など、**変わりやすい情報には、本文に時点を書く**（例：「2025年の売上高で」「2026年11月時点で」）。
- 出典ファイルには、その情報を**確認した日付**を書く。
- 策定中・審議中のものは「確定した」と書かない。

### 4.5 出典ファイルの書き方（必須）

`materials/<テーマ>/SOURCES.md` に、次の形で書く。

```
# 出典（<テーマ名>）

確認日：YYYY-MM-DD

## NN-<名前>.md

### <## の見出し>
- <資料名>（<発行元>）<URL>（ランクA、確認日 YYYY-MM-DD）
- <資料名>（<発行元>）<URL>（ランクB）
- 異説：<何が食い違ったか。どれを採用し、なぜか>
- 未確認：<実際には開いていないURLや、照合が1つだけの事実>
```

- **実際に開いて読んだ資料だけを書く。** 記憶で書いたURLは「未確認」と明記する。

## 5. 内容のルール

- **中立**：意見が分かれる話題（歴史の評価、政治、企業の優劣など）は、主な立場を並べて書く。どれか1つを正しいと断定しない。
- **安全**：
  - セキュリティの教材は**守る側の知識**として書く。攻撃の手口は「どういうものか・なぜ危ないか・どう防ぐか」までにする。実行手順、攻撃に使えるコードやコマンドは**禁止**。
  - 医療・法律・お金の判断に直接使われる内容は、一般的な知識にとどめる。
- **個人情報**：実在の一般人の名前や個人情報は書かない（歴史上の人物、公人、企業の代表者は可）。

## 6. テーマ別のルール

新しいテーマを追加するときは、この章に同じ形で節を足す（レベル・範囲と分け方・書き方の重点・確認の重点）。

### 6.1 世界史（`world-history`）

- **レベル**：高校世界史（世界史探究）の通史。大きな流れを説明できることが目標。
- **範囲と分け方**：01 古代文明とギリシア・ローマ／02 アジアの古代帝国／03 中世／04 近世／05 近代／06 現代。
- **書き方の重点**：
  - 「なぜ起きたか → 何が起きたか → 何が変わったか」の順で書く。年号の羅列にしない。
  - 地域どうしのつながり（交易・戦争・思想の伝わり方）を書く。
- **確認の重点**：年号・人名の表記・王朝名は、教科書や大学・博物館の解説で確認する。学説が分かれる年号は教科書の値を使い、異説を記録する。

### 6.2 半導体（`semiconductor`）

- **レベル**：仕事で業界の話についていけるビジネス教養。理系の知識がなくても読める。
- **範囲と分け方**：01 しくみ／02 種類と用途／03 製造工程／04 業界の構造と主要企業／05 最新動向と地政学。
- **書き方の重点**：
  - 専門用語は最初に定義し、例えを1つ添える（例：露光＝回路の写真を焼き付ける）。
  - 企業名を答えにする問題では、選択肢に並ぶほかの語も企業名になるように、同じ段落で複数の企業を太字にしない。
- **確認の重点**：数字・シェア・製造プロセスの世代・補助金額は、企業の公式発表・業界団体（WSTS、SIA、SEMI）・政府資料（経済産業省など）で確認する。

### 6.3 C++（`cpp`）

- **レベル**：プログラミングの基礎を知っている人向けの、入門〜中級の「頭の地図」。
- **範囲と分け方**：01 成り立ちと特徴／02 基本の文法／03 ポインタとメモリ管理／04 クラスとオブジェクト指向・テンプレート／05 標準ライブラリとモダンC++。
- **書き方の重点**：
  - **コードは書かない**（2.7）。機能名はそのまま本文に書く（例：std::vector、unique_ptr）。
  - 「何のための機能か → どう使うか → 何に気をつけるか」の順で書く。
  - 規格の年（C++11、C++17 など）は、その規格で入った代表的な機能とセットで書く。
- **確認の重点**：どの規格で入った機能かは、cppreference.com や isocpp.org で確認する。策定中の規格（C++26 など）は、確認した時点の状況だけを書く。

### 6.4 サイバーセキュリティ（`security`）

- **レベル**：社会人の教養〜情報セキュリティマネジメント試験・基本情報技術者試験のセキュリティ分野。
- **範囲と分け方**：01 基本の考え方／02 攻撃の手口／03 守る技術／04 組織の対策と法律／05 最新動向。
- **書き方の重点**：
  - 5章の「安全」を必ず守る。手口には必ず対策をセットで書く。
  - 用語は試験で使われる正式な名前を優先する。
  - IDやOSのような短い英字の略語は、太字にしない（意味のある問題にならないため）。
- **確認の重点**：用語と定義は IPA・国家サイバー統括室（旧NISC）・JPCERT/CC・総務省・警察庁で確認する。法律は e-Gov 法令検索で正式な名前と施行状況を確認する。

## 7. 品質チェック（提出前に必須）

### 7.1 機械のチェック（アプリと同じ部品で検査する）

教材ファイルを置いたら、リポジトリのフォルダで次を実行する。

```bash
npm run check:materials
```

- 自分のファイルだけを検査する：`MATERIALS_FILTER=cpp/03 npm run check:materials`
- 作られたカードと問題を全部表示する：`MATERIALS_DUMP=1 MATERIALS_FILTER=cpp/03 npm run check:materials`

合格の条件（すべて**必須**）：

| チェック | 合格の条件 |
|---|---|
| 問題の有無 | すべてのカードに問題が1問以上ある |
| 最後の手段の問題 | 書き方の手がかりがなく、仕方なく作った問題（fallback）が全体の10%以下 |
| 答えの見え方 | 4択の問題文に答えが出ていない |
| カードの長さ | どのカードも286字以下（目安は120〜220字） |

このコマンドを実行できない環境（Deep Research など）では、7.2のチェックを特にていねいに行い、報告書に「機械のチェック未実施」と書く。依頼者が提出後に実行する。

### 7.2 目で見るチェック（必須）

`MATERIALS_DUMP=1` で表示された問題を**全部読み**、次に当てはまる問題があれば、**元の文を書き直す**。

- [ ] 文脈がなく答えられない穴埋め（「これを（　）という」）
- [ ] 正解が2つ以上ありうる
- [ ] 選択肢に、種類の違う語が混ざっていて一目でハズレとわかる（人名を問うのに「〜戦争」など）
- [ ] ○×の文が、明らかにおかしくて考えなくても×とわかる
- [ ] 問題文や同じカードの別の問題に、答えが出ている
- [ ] 数字の選択肢が、見分けのつかないほど近い

書き直しても直らない問題は、報告書の「アプリへの要望」に書く。

## 9. Deep Research などにそのまま貼るプロンプト

コマンドを実行できないAIに頼むときに使う。`{ }` の部分を書き換えて、**この文書の2章・4章・5章と、6章の該当テーマの節を、プロンプトの後ろに貼り付けて**渡す。

```
あなたは教材ライターです。スマホで「ながら勉強」するためのアプリに取り込む学習教材を、日本語のMarkdownで作ってください。
このアプリは、本文を120〜220字のカードに自動で区切り、太字の語・「〇〇とは、△△である。」の文・「用語：説明」の行・「Q:」「A:」の組・単位付きの数字から、穴埋めや4択の問題を機械的に作ります。書き方がそのまま問題の質になります。

【テーマ】{テーマ}
【このファイルの範囲】{例：近代 — 市民革命・産業革命・国民国家・帝国主義}
【レベル】{6章の該当テーマのレベル}
【分量】本文 5,000〜8,000字。「##」の小単元を6〜10個。

【守るルール】
下に貼り付けた「書き方のルール」「情報源のルール」「内容のルール」「テーマ別のルール」をすべて守ってください。特に次の点は必ず守ってください。
- 年号・数字・人名・地名は、2つ以上の信頼できる情報源で照合する。Wikipediaだけを根拠にしない。確認できないことは書かない。
- 1文は60字以内、1段落は2〜4文。「これ」「その」で始まる段落を作らない。
- 各段落で一番大事な名詞を1〜2個 **太字** にする。太字の語は同じ文の中で繰り返さない。答えが1つに決まる文で太字にする。
- 各「##」の最後に「用語：説明」を3〜5行、「Q:」「A:」の確認問題を2組。
- 表・画像・URL・脚注・コード・バッククォートを本文に入れない。文章を書き写さず、自分の言葉で書く。
```
